# 学祭精算 v1.0

学祭の出店における利益分配、貢献度ポイント、経費立替、運営資金拠出、送金済み履歴を管理する、**完全静的・無料・スマホ対応**のWebアプリです。

## 機能

- 参加者の追加・名前変更・削除（履歴がある人は削除を防止）
- 準備・買い出し・車出し・当日運営・その他の貢献を、回数×単価で記録
- 経費を「参加者が立替」か「運営金庫から支払った」かに分けて登録
- 出店前に参加者が金庫へ渡した運営資金（返金対象）を登録
- 売上総額を手入力（売上明細・POS機能なし）、留保金を設定
- 利益を貢献ポイント比率で配分。1円単位の端数まで自動調整
- 利益配分と立替金・拠出金返済額を合算して精算。誰が誰にいくら払うかを提案
- 実際に送金済みとなった支払いを記録し、残額を再計算
- JSONバックアップ／復元、CSV書き出し、オフラインキャッシュ、ホーム画面追加（PWA）

## 会計上の前提

- 売上金はすべて「運営金庫」に入り、金庫払いの経費は同じ金庫から支出したものとします。
- 売上総額は入力した値を使用します。明細ごとの商品売上は集計しません。
- 経費の総額は支払元に関係なく利益から控除します。
- 個人立替は利益配分とは別の債権（返済対象）です。
- 拠出金は金庫に一時的に預けた資金であり、経費でも売上でもありません。残額に返金対象として加算します。
- 売上 − 経費 − 留保金が赤字の場合は**損失の負担を自動決定しない**ため、自動精算案を停止します。
- 利益があるのに誰も貢献ポイントを持たない場合も、自動配分を停止します。
- ポイント配点は新規記録にのみ反映され、過去の記録のレートは保存した値を用います。
- アプリから実際の銀行振込や現金移動は行いません。「支払いを記録」は完了後のみ使用してください。

## 動かし方（PCでの試用）

展開先のディレクトリで次を実行し、ブラウザから http://localhost:8000 を開きます。

```shell
python -m http.server 8000
```

`index.html` を直接開くこともできますが、Service Workerによるオフライン機能は動作しません。

## スマホで無料公開（GitHub Pages）

1. GitHub Freeで新しい**公開リポジトリ**を作成します（例：`gakusai-settlement`）。
2. ZIP展開後のファイルをリポジトリのルートへアップロードします。**個人の記録JSONやCSVをリポジトリにアップロードしないでください。**
3. GitHubの **Settings → Pages → Build and deployment → Deploy from a branch** を選び、`main` ブランチの`/(root)`から公開します。
4. 公開URL（例：`https://ユーザー名.github.io/gakusai-settlement/`）をスマホで開き、ブラウザの「ホーム画面に追加」を利用します。

GitHub Pagesのサイトは基本的に公開サイトです。現行実装はコードのみ公開し、個人データは利用者の端末に保存される構成です。

## データの保存・制限

- すべての記録はブラウザ内の `localStorage` に自動保存されます。**複数端末間の同期・共有編集はありません。**
- 同じURLを複数の人が開いても各自のデータは独立します。
- 閲覧履歴の削除、端末故障、ブラウザストレージ消去などでデータが失われます。**JSONバックアップを毎日または重要な変更の前後に保存してください。**
- JSON復元は現在データを置き換えます。CSVは閲覧・会計確認用のエクスポートであり、復元ファイルではありません。
- PWAのオフライン機能は、初回のサイトアクセス後にキャッシュされる必要があります。
- 単一イベント・単一通貨（円）を前提としています。複数イベントの管理は、別々のバックアップを使う運用です。

## 精算式

```
利益配分総額 = 売上総額 − 全経費 − 留保金
個人利益配分 = 利益配分総額 × (個人貢献ポイント ÷ 全参加者ポイント合計)
個人受取残額 = 利益配分 + 個人立替 + 拠出金 + 送金済（支払側）− 送金済（受取側）
運営金庫残額 = 売上 + 拠出金 − 金庫払いの経費 − 金庫からの支払 + 金庫への入金
精算可能残高 = 運営金庫残額 − 留保金
```

円単位の端数は最大剰余方式で分配し、全員の利益配分合計が利益配分総額と一致するよう調整します。赤字・ポイント未設定時は精算案を停止します。
